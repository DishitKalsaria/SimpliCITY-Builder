# Release SimpliCITY Builder v0.1.5

**Status: external testing candidate; not declared stable.** Creator: Dishit Kalsaria.

## Pre-tag checks

- Run `python3 -m unittest discover -s tests -v` and verify green GitHub Actions (unit, four sample builds, desktop/mobile Chromium).
- Verify the four demo worlds and manual screenshot review for composition and touch targets.
- Run publishing preparation using only fictional sample data; confirm no upload occurs and social-preview metadata is correct.
- Review [RELEASE_ACCEPTANCE.md](RELEASE_ACCEPTANCE.md) for external installed-skill and link-only AI-host tests. Do not commit private résumés or evidence reports.

## Tag for external testing

After the v0.1.5 source is committed and pushed, confirm CI and create **an annotated testing tag**:

```bash
git status -sb
git pull --ff-only
git tag --list
git tag -a v0.1.5-rc.1 -m "SimpliCITY Builder v0.1.5 external testing"
git push origin v0.1.5-rc.1
```

If a tag with that name already exists, **do not overwrite it**. Use a new `-rc.N` tag. On GitHub, mark the corresponding Release as **pre-release**, not stable.

## Package and checksum the exact tag

Clone the testing tag into a clean directory, then run the included archive scripts:

```bash
git clone --depth 1 --branch v0.1.5-rc.1 https://github.com/DishitKalsaria/SimpliCITY-Builder.git verify-v015
cd verify-v015
python3 scripts/package_release.py --label v0.1.5-rc.1
```

Attach the generated installable Skill ZIP, complete GitHub-source ZIP, and `SHA256SUMS.txt` to the matching pre-release. Verify the downloaded checksum files together using `sha256sum -c SHA256SUMS.txt` or `shasum -a 256` on macOS.

The standard GitHub source archive is **not** the installable skill ZIP. Release assets can be generated by CI or locally from the same tagged commit, but do not mix files built from different revisions.

## Final tag after acceptance

After external acceptance results are recorded, make any fixes on `main`, rerun checks, and **only then** tag the approved commit as `v0.1.5`. Package and hash that exact tag and publish its GitHub Release. Never move published tags. If fixes are required after release, use a subsequent version.

Optional external Agent Skills specification validation (`skills-ref`) is not part of current CI; do not claim it was run unless performed separately.
