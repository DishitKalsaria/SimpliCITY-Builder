Link-based use requires an AI agent with file retrieval, résumé parsing, Python execution and downloadable file support. **A URL does not install the skill.** Do not execute unreviewed code from a mutable branch. Ask the user for permission to run source code and prefer tagged, reviewed releases.

1. Open the [repository](https://github.com/DishitKalsaria/SimpliCITY-Builder) and review `README.md`, `AI_START_HERE.md`, `simplicity-builder/SKILL.md` and `SECURITY.md`.
2. After the `v0.1.3` tag exists, in an authorized execution environment use `git clone --depth 1 --branch v0.1.3 https://github.com/DishitKalsaria/SimpliCITY-Builder.git` and inspect the code before executing.
3. When `git` is unavailable, download the **release asset** from `https://github.com/DishitKalsaria/SimpliCITY-Builder/releases/tag/v0.1.3` and verify its published checksum. Request approval before running the extracted source.
4. Only if these methods fail, read individual source files as text via GitHub/browser retrieval; raw links are *not* a runtime installation substitute. For development from `main`, obtain explicit approval, acknowledge the mutable branch, and review the code. Do not treat `main.zip` as a verified release.
5. If retrieval or execution is unavailable, ask the user to upload the installable skill ZIP to a compatible host; do not claim a build you couldn't run.

**Prompt:** “Use SimpliCITY Builder from the pinned `v0.1.3` GitHub release. I've attached my résumé. Create a moonlit train-and-windmill world, with the illustrated landmarks themselves clickable. Build and validate a downloadable, mobile-friendly offline portfolio. Do not invent facts or publish private details. Report any unavailable checks.”
